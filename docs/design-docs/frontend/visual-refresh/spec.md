# Feature: 家长端页面视觉焕新

**作者**: Codex  
**日期**: 2026-07-30  
**状态**: Completed

---

## 1. 背景 (Background)
### 1.1 问题描述
- 当前页面的信息层级不够清晰，首页横幅、统计、AI 问答、快捷入口、分类与链接内容之间的主次关系不够突出，家长需要花费额外注意力判断下一步操作。
- 整体视觉偏灰白、偏后台管理工具，缺少面向家长用户的亲和力以及与育儿场景相符的轻松、温暖氛围。
### 1.2 现状分析
- 当前项目是基于 Vue 3、Vite 和原生 CSS 构建的育儿资源导航应用，同时支持 Web 与 Tauri 桌面端。
- 页面由顶部导航、年龄阶段侧栏、首页仪表盘、链接库、AI 问答区及链接/分类管理弹窗组成。
- 用户选择孩子的年龄阶段后，首页推荐、热门分类、最近添加、收藏内容及链接库会随之筛选；链接数据通过统一 store 管理，并持久化到浏览器 localStorage 或 Tauri 本地数据文件。
- 现有视觉以灰白背景、靛蓝主色、细边框和小字号为主，整体更接近后台管理界面；彩色分类图标和局部渐变已有一定活力，但品牌感、页面层次和整体一致性仍较弱。
- 全局视觉变量集中在 `src/style.css`，组件样式主要分散在各 Vue 组件的 scoped CSS 中，部分颜色和状态样式采用硬编码。
### 1.3 主要使用场景
- 家长根据孩子的年龄阶段查看更匹配的育儿知识、健康医疗、亲子阅读及实用工具。
- 家长通过首页推荐、热门分类、统计入口和搜索快速找到所需资源。
- 家长收藏、添加、编辑、删除及分类管理自己的常用育儿链接。
- 家长通过 AI 问答区获取辅助性的育儿信息。

## 2. 目标 (Goals)
- 通过视觉层级重组，让家长能够更快区分页面主任务、重点信息与辅助内容。
- 将整体页面调整为清新、活泼且有亲和力的育儿主题，同时避免过度幼稚或影响内容阅读。
- 统一主要页面和弹窗的配色、圆角、卡片、间距、阴影与交互反馈，提升整体一致性。
- 在视觉改造完成后补齐 AI 输出、外链、数据导入、分类管理和旧数据升级的安全与可靠性边界。
- 统一首页与链接库的筛选语义，并保证移动侧栏在视觉关闭时也从辅助技术和键盘导航中关闭。
### 2.1 非目标 (Non-Goals)
- 除修复已确认的行为偏差外，不扩展新的业务功能。
- 不引入远程后端或新的云端持久化服务；本地数据仅增加兼容旧数据所需的版本迁移。
- 不新增独立业务功能，不重构 AI 问答、链接管理或分类管理的数据逻辑。

## 3. 需求细化 (Requirements)
### 3.1 功能性需求
- 统一升级全局配色、字体层级、间距、圆角、阴影、按钮、表单、标签及弹窗等基础视觉规范。
- 调整顶部导航、年龄阶段侧栏和页脚的视觉表现，使应用品牌与页面导航更清晰、更具亲和力。
- 调整首页年龄阶段横幅、育儿贴士、统计卡片、AI 问答、快捷入口、热门分类、最近添加、系统推荐和收藏区域的视觉层级。
- 将 AI 问答下方的快捷入口、最近添加、热门分类、系统推荐和收藏链接整合为单一 Tab 内容区，减少纵向堆叠并保持原有入口能力。
- 调整链接库的搜索、筛选、操作按钮、链接卡片和空状态，使浏览与管理路径更易识别。
- 调整 AI 问答区及其设置弹窗的视觉风格，使其与全局育儿主题保持一致。
- 调整链接编辑、分类管理和分类编辑弹窗的视觉风格，使表单、状态和操作区域保持一致。
- 为可交互元素提供清晰且一致的悬停、聚焦、按下和选中反馈。
- 保持现有页面功能、事件、数据流、文案语义和持久化行为不变。
- AI 远程回答不得以未清洗 HTML 进入 DOM；Web 端不得持久化 API Key，并应清理旧的明文 Key。
- 导入和分类管理必须通过 store 的统一持久化接口完成，保存失败时不得假装成功。
- 链接只允许打开 `http:` / `https:` 地址，新窗口必须与来源窗口隔离。
- Dashboard 与链接库统一按链接自身的年龄字段筛选；“最近添加”和收藏筛选的查看全部语义保持一致。
- 旧持久化数据应自动迁移，保证默认推荐标识和现有用户数据同时保留。
- 移动端关闭侧栏后，其内部控件不得继续出现在键盘 Tab 顺序或辅助技术导航中。
- “实用工具 - 疫苗接种”应提供基于国家免疫规划 2026 年版的完整时间表、当前成长阶段提示、补种原则、接种前后注意事项及官方来源，并明确不能替代接种门诊的个体化评估。
- “实用工具 - 生长曲线”应支持多孩档案切换、孩子新增/改名，以及按孩子隔离的身高、体重和可选头围记录；数据归属于当前数据空间并参与同步与导入导出，不提供医学诊断或生长百分位结论。
### 3.2 非功能性需求
- 兼容现有 Web 浏览器与 Tauri 2 桌面 WebView，重点保证默认 1200 × 800 桌面窗口正常显示。
- 保持现有 768px、640px、480px 等窄屏场景的可用性，避免横向溢出、布局错位或主要操作不可见。
- 不依赖外部字体、CDN 或远程装饰图片，确保 Tauri CSP、离线使用和本地打包不受影响。
- 优先使用 CSS 变量、渐变、阴影、图形装饰和现有 Lucide 图标完成视觉焕新，不显著增加打包体积。
- 动效应轻量且不干扰操作，并兼容 `prefers-reduced-motion` 系统设置。
- 文字与背景需保持足够对比度；键盘聚焦状态与触屏下的操作入口应清晰可见。
- 改动应在现有未提交代码上增量实施，不覆盖用户已有修改。

## 4. 设计方案 (Design)
### 4.1 方案概览
- 采用“全局视觉系统 + 页面骨架调整 + 组件局部焕新”的渐进式方案，在保留现有组件结构和业务契约的前提下统一视觉语言。
- 全局视觉层由 `src/style.css` 承担，扩充清新育儿主题的语义变量，并统一按钮、表单、标签、卡片及弹窗等基础控件。
- 页面骨架层由 `App.vue`、`Header.vue` 和 `CategoryNav.vue` 承担，负责整体背景、导航层级、侧栏与内容区关系及响应式布局。
- 功能组件层由 `Dashboard.vue`、`AISearch.vue`、`SearchBar.vue`、`LinkList.vue` 及管理弹窗承担，各组件共享全局视觉语言，同时保留自身内容特色。
- 依赖方向保持为“全局视觉变量与基础控件 → 页面骨架与响应式布局 → 组件局部视觉 → 现有组件状态与业务数据”。视觉层只读取分类色、年龄色和组件状态，不修改 store、props、events 或业务数据流。
- 装饰效果使用 CSS 渐变、柔和色块、伪元素和现有 Lucide 图标实现，不引入外部字体、远程图片或新的运行时依赖。
- 选择渐进式调整而不新增完整 UI 组件库，可降低对当前未提交功能代码的干扰和回归风险；代价是部分 scoped CSS 仍保留少量重复，但与当前项目规模和改动目标匹配。
### 4.2 组件设计 (Component Design)
#### 4.2.1 核心类/模块设计
- `src/style.css` 为主题与基础控件模块，统一维护色彩、层级、间距、圆角、阴影、焦点、动效及响应式基础规则。
- `App.vue` 为应用外壳模块，负责页面背景、主内容宽度、侧栏占位、链接库工具栏和页脚布局。
- `Header.vue` 为品牌导航模块，负责突出产品品牌、当前视图和全局操作。
- `CategoryNav.vue` 为年龄上下文模块，仅负责年龄阶段选择及移动端侧栏呈现，不恢复已经移除的分类管理职责。
- `Dashboard.vue` 为首页信息层级模块，保持现有内容结构，将年龄阶段与 AI 助手作为主要入口，统计和快捷入口作为次级操作，资源列表作为内容区。
- `Dashboard.vue` 的五类次级内容共享一个 Tab 容器；默认展示快捷入口，切换时仅渲染当前面板，Tab 支持方向键、Home/End 和移动端横向滚动。
- `SearchBar.vue` 与 `LinkList.vue` 共同构成资源浏览模块：搜索框负责查询入口，链接列表负责筛选状态、资源卡片和管理操作。
- `AISearch.vue` 为独立 AI 子体验模块，保留自身状态与业务逻辑，但配色、卡片及弹窗统一使用全局视觉系统。
- `src/data/store.js` 成为分类、链接、导入替换和数据迁移的唯一写入口；组件不得直接修改持久化集合。
- 外链协议校验与安全打开封装为独立工具，Dashboard、链接库和导入校验共享同一规则。
- AI 结果使用 Vue 文本插值和保留换行的 CSS 展示，不使用 `v-html`；API Key 仅保存在当前内存会话。
- `LinkModal.vue`、`CategoryManager.vue` 和 `CategoryModal.vue` 构成管理弹窗模块，共享全局表单和弹窗视觉，仅保留各自业务布局差异。
- `VaccineGuide.vue` 负责疫苗接种攻略展示，静态规范数据由 `src/data/vaccineGuide.js` 提供；Dashboard 只负责打开入口并传入当前成长阶段。
- `GrowthTracker.vue` 负责孩子选择/管理、成长记录录入、指标切换、趋势图和历史管理；纯图表坐标计算由 `src/utils/growthChart.js` 提供，孩子与记录通过 `store` 的统一写接口持久化。
- 不新增复杂组件抽象；跨组件一致性优先通过 CSS 变量和公共基础类实现，避免为视觉焕新扩大重构范围。
#### 4.2.2 接口设计
- 本次不新增或修改业务接口，所有组件公开契约保持向后兼容。
- `Header.vue` 保留 `currentView` 属性及 `refresh`、`menu`、`view-change` 事件。
- `CategoryNav.vue` 保留 `age-stage-change(Array<string>)` 事件。
- `Dashboard.vue` 保留 `selectedAgeStages` 属性及 `category-select`、`view-all-links`、`clear-age-stage`、`stat-click` 事件。
- `SearchBar.vue` 保留现有 `modelValue` / `update:modelValue` 双向绑定契约。
- `LinkList.vue` 保留分类、搜索词、年龄阶段和筛选模式属性，以及添加、编辑、删除和返回事件。
- 链接及分类管理弹窗保留现有显示状态、编辑对象、父分类属性，以及关闭、保存、刷新事件。
- store 继续作为分类和链接数据的唯一来源，视觉层不向持久化数据写入视觉状态。
- 新增 CSS 语义变量仅作为内部视觉契约，由组件样式读取，不向业务代码暴露。
#### 4.2.3 数据模型
- 本地数据根对象包含 `schemaVersion`，当前版本为 3。
- 读取无版本旧数据时保留用户分类、链接和收藏状态，并按稳定的内置链接 ID 补充 `isDefault`。
- 导入数据必须至少包含合法的 `categories` 与 `links` 数组，链接 URL 必须为 `http:` 或 `https:`。
- 快照包含 `growthChildren` 与 `growthRecords`；历史记录确定性归入默认孩子，当前记录通过 `childId` 关联孩子档案。
#### 4.2.4 并发模型
- N/A - 本需求不涉及线程、异步任务或共享状态访问方式变更。
#### 4.2.5 错误处理
- store 写操作失败时向调用方抛出错误，由界面给出明确失败反馈；不得只记录日志后继续关闭弹窗。
- AI 历史记录和旧持久化数据解析失败时回退到安全默认值，同时清理损坏的局部配置。
- OpenAI 非 2xx 响应应转换为可理解的错误，不渲染服务端返回的任意 HTML。
- 当运行环境不支持个别 CSS 装饰效果时，使用纯色背景、基础阴影和标准布局自然降级，不影响内容访问和业务操作。
### 4.3 核心逻辑实现
- 扩充全局语义变量，将颜色划分为品牌主色、薄荷绿辅助色、暖黄色强调色、柔和背景层、卡片层和文字层，减少组件对通用颜色的重复硬编码。
- 重建页面视觉层级：背景作为最低层，导航和侧栏作为稳定框架，年龄横幅与 AI 区作为一级重点，统计和快捷入口作为二级操作，资源列表作为三级内容。
- AI 区域下方使用单行 Tab 导航承载五类次级内容，桌面端平均分配宽度，窄屏横向滚动；面板切换不修改筛选、跳转或链接打开逻辑。
- 保留分类和年龄的原始数据色，仅用于图标、标签和局部边框；大面积背景统一使用低饱和主题色，避免多种高饱和颜色竞争视觉注意力。
- 统一响应式规则：1200px 保持合理双栏，992px 调整内容比例，768px 切换移动导航与单栏布局，480px 压缩间距及按钮密度。
- 统一交互状态：悬停时轻微上浮、按下时回落、键盘聚焦时使用明确描边，触屏场景下操作入口始终可见。
- 动效仅使用轻量的颜色、阴影和位移动画；系统启用 `prefers-reduced-motion` 时关闭非必要动画。
- 最后逐页检查横向溢出、文字对比度、弹窗高度及 Tauri 默认窗口布局，不修改业务脚本、组件契约或数据处理逻辑。
- 不新增运行时依赖、外部字体或图片请求，保持当前打包体积级别。
- 动画优先使用 `transform` 与 `opacity`，避免持续动画大面积修改阴影、模糊或布局尺寸；移除或限制链接卡片现有的无限发光动画。
- 谨慎使用大面积 `filter`、`backdrop-filter` 和多层高模糊阴影，保证 Tauri WebView 与低性能设备流畅。
- 不新增 JavaScript 布局监听器或运行时尺寸计算，响应式继续由 CSS 媒体查询完成。
- 使用生产构建和关键响应式断点检查验证资源与渲染性能无明显回退。
### 4.4 方案优劣分析
- **优点**：
  - 改动集中在表现层，业务回归风险较低。
  - 全局语义变量能够统一页面风格，并便于后续调整主题。
  - 不增加外部资源与依赖，继续支持离线使用及 Tauri CSP。
  - 同时覆盖桌面、Tauri 默认窗口、手机断点和可访问交互状态。
- **局限**：
  - 现有 scoped CSS 较多，仍会保留少量跨组件重复样式。
  - 不引入插画与自定义字体，品牌表现主要依靠颜色、图形、间距和现有图标。
  - `Dashboard.vue` 体积较大，本次为控制范围不进行结构性拆分。
- **风险与控制**：
  - 硬编码颜色可能造成局部不一致：逐组件检查，并将通用颜色迁移到语义变量。
  - 响应式调整可能影响默认 1200 × 800 布局：将其作为重点验证尺寸。
  - 工作区已有未提交功能代码：仅增量修改，并通过 diff 核对不覆盖既有逻辑。
  - 动效和装饰可能降低性能或可读性：限制高成本效果，并检查文字对比度。

## 5. 备选方案 (Alternatives Considered)
- **只修改 `:root` 颜色变量**：改动最小，但大量 scoped CSS、行内颜色和硬编码状态色不会同步变化，也无法解决信息层级不清的问题，因此不采用。
- **引入 UI 框架或重建公共组件库**：一致性更强，但会新增依赖并扩大模板与交互重构范围，不符合“功能不变、增量调整”的边界，因此不采用。
- **同时拆分 `Dashboard.vue` 并重构页面结构**：长期维护性更好，但会显著提高对当前未提交功能代码的干扰和回归风险，因此留作后续独立重构。
- **使用外部插画、在线字体或远程背景素材**：氛围表现更直接，但影响离线使用、Tauri CSP、加载性能和风格可控性，因此不采用。
- 最终继续选择“全局语义变量 + 现有组件局部焕新”的渐进式方案。

## 6. 业界调研 (Industry Research)

> **注意**：本章节应在完成自主设计后填写，用于验证方案、确保下限，而非作为设计的起点。

### 6.1 业界方案
- W3C WCAG 2.2 建议普通文字与背景至少达到 4.5:1 对比度，大号文字至少达到 3:1；本项目的低饱和装饰色不能替代可读文字色。[WCAG 2.2 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)
- W3C 对键盘焦点外观的说明推荐使用清晰、连续且足够粗的轮廓；本项目统一采用至少 2px 的 `:focus-visible` 描边。[WCAG 2.2 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)
- W3C WCAG 2.2 的目标尺寸最低要求为 24 × 24 CSS 像素；频繁使用的按钮和触屏入口优先提供更大的可点击区域。[WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)
- MDN 说明 `prefers-reduced-motion` 已广泛支持，可用于检测并减少非必要动画；本项目使用该媒体查询统一关闭装饰性动画。[MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)
- Material Design 3 的 canonical layouts 将 bar、rail 和 pane 视为可随断点调整的页面骨架区域；本项目借鉴该思路，将 Header、年龄侧栏和主内容视为独立响应式区域，而不照搬其组件库。[Material Design 3 Canonical Layouts](https://m3.material.io/foundations/layout/canonical-examples/overview)
### 6.2 对比分析
- 本方案与业界实践一致地采用语义化颜色、明确焦点状态、足够触屏尺寸和基于断点的页面骨架调整。
- 与完整设计系统不同，本项目不引入新的组件库或设计依赖，只提取当前页面所需的视觉原语，降低迁移成本。
- 低饱和背景和多彩局部强调能够营造亲和力，但所有正文与操作状态仍以对比度和可识别性为先。
- 响应式布局根据现有 1200/992/768/480 断点渐进调整，不复制 Material 的固定窗口尺寸分类，避免与当前 Tauri 默认窗口和组件结构冲突。
