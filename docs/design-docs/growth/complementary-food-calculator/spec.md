# Feature: 辅食搭配计算器

**作者**: Codex  
**日期**: 2026-08-20  
**状态**: Approved（已实现并验收）

---

## 1. 背景 (Background)

### 1.1 问题描述

- 首页已有“辅食计算器/辅食添加”入口，但点击后只显示“功能开发中”，无法帮助照护者完成实际决策。
- 照护者最常见的问题不是精确计算营养素，而是“当前月龄一天吃几次、食物做到什么性状、今天搭配是否够多样、有没有富铁食物、首次尝试新食物要注意什么”。
- 辅食建议属于健康信息。功能必须给出清晰边界，避免把通用指南包装成个体化处方或医学诊断。

### 1.2 现状分析

- `src/components/Dashboard.vue` 统一维护实用工具入口；`food` 动作目前落入通用开发中提示。
- 项目采用 Vue 3 组合式 API；现有 `VaccineGuide.vue`、`GrowthTracker.vue` 和 `GrowthSchedule.vue` 已提供弹框、焦点管理、响应式布局与免责声明的可复用交互范式。
- 当前数据模型不包含出生日期；因此本期使用直接月龄输入，不从孩子档案推断。
- 本功能不需要远端服务，也不修改用户数据 Schema；所有计算在浏览器内同步完成。

### 1.3 主要使用场景

- 照护者输入孩子月龄，快速查看该阶段的餐次、食物性状与喂养重点。
- 照护者勾选今天已吃的食物组，检查食物多样性、谷薯/蔬果/富铁动物性食物是否覆盖。
- 首次尝试一种新食物时，快速查看单一引入、观察过敏和噎食风险提醒。
- 照护者直接输入月龄并获得即时建议，不需要先选择孩子档案。

## 2. 目标 (Goals)

- 将占位入口升级为一个 1 分钟内可完成的月龄适配与今日搭配检查工具。
- 输出简短、可行动、来源可追溯的建议，并明确“不替代医生或营养师评估”。
- 保持离线可用、移动端易操作，并与现有工具弹框视觉和键盘交互一致。

### 2.1 非目标 (Non-Goals)

- 不计算个体每日热量、蛋白质、微量营养素或精确克数。
- 不提供疾病、早产、低出生体重、严重湿疹、已知过敏或生长异常儿童的个体化方案。
- 不建设完整食谱库、采购清单、喂养打卡或云端历史记录。
- 不替代母乳/配方奶喂养，也不评价孩子是否“达标”。

## 3. 需求细化 (Requirements)

### 3.1 功能性需求

- `food` 快捷入口在默认视图和年龄阶段视图中均打开辅食计算器弹框。
- 用户可输入 0—36 月龄；系统按 `<6`、`6—8`、`9—11`、`12—23`、`24—36` 月龄输出阶段建议。
- 系统展示与月龄匹配的辅食餐次、食物性状、关键重点；未满 6 月龄时突出“通常约 6 月龄开始并观察准备信号”。
- 功能不区分孩子档案，仅以当前输入月龄计算通用建议。
- 用户可勾选中国营养喂养评估使用的 7 类食物组，系统即时计算今日多样性，并分别检查：
  - 是否覆盖至少 4 类食物；
  - 是否包含谷薯类；
  - 是否包含蔬果；
  - 是否包含富铁动物性食物。
- 用户可标记“今天首次尝试新食物”，系统显示单一食物引入、观察不良反应及高风险儿童咨询医生的提醒。
- 系统始终展示重点安全提示：不强迫进食、避免噎食形态、少糖少盐；12 月龄以下额外提醒蜂蜜和牛奶作为主要饮品的限制。
- 系统展示官方资料来源和内容更新时间，外链使用项目已有的安全打开方法。
- 弹框支持遮罩点击、关闭按钮、Escape、Tab 焦点约束和关闭后焦点恢复。

### 3.2 非功能性需求

- 所有计算为本地纯函数，用户输入不上传、不持久化；无网络时功能完整可用。
- 计算复杂度为 O(G)，其中 G 固定为 7 个食物组；交互更新应在一帧内完成。
- 375px 宽屏幕无横向滚动，桌面端弹框最大宽度不超过 1080px，内容区独立滚动。
- 颜色之外必须有文字和图标表达状态；可交互元素提供可读标签和键盘焦点。
- 指南数据与 Vue 组件分离，后续更新建议或来源时无需修改计算逻辑和页面结构。
- 不变更现有持久化 Schema、登录、同步及其他工具行为。

## 4. 设计方案 (Design)

### 4.1 方案概览

- 新增独立的辅食领域模块，集中维护年龄阶段、7 类食物组、官方来源和纯计算函数。
- 新增一个无服务端依赖的 Vue 弹框组件；组件只管理表单状态并消费领域模块的计算结果。
- `Dashboard.vue` 只负责挂载弹框和路由 `food` 动作，依赖方向保持为 Dashboard → 组件 → 纯数据/计算模块。
- 选择“指南检查器”而非“营养克数计算器”，以低输入成本换取更高的可理解性和更低的误导风险。

### 4.2 组件设计 (Component Design)

#### 4.2.1 核心类/模块设计

- `src/data/complementaryFoodGuide.js`：静态指南数据、年龄阶段匹配、搭配检查与安全提示生成；不依赖 Vue、Store 或 DOM。
- `src/components/FoodCalculator.vue`：月龄输入、食物组选择、结果卡片、来源与弹框交互。
- `src/components/Dashboard.vue`：维护 `showFoodCalculator` 并把所有 `food` 动作路由到弹框。

#### 4.2.2 接口设计

- `getFeedingStage(ageMonths)`：接收有限数值月龄，返回不可变阶段配置；非法输入抛出 `TypeError`。
- `evaluateFoodDiversity(selectedGroupIds)`：接收食物组 ID 数组，返回去重后的数量、覆盖项和下一步提示；未知 ID 抛出 `TypeError`。
- `getSafetyTips(ageMonths, isTryingNewFood)`：返回与月龄和首次尝试状态匹配的安全提示数组。

#### 4.2.3 数据模型

- 本期只有代码内静态配置和组件瞬时状态，不新增持久化字段、索引或迁移。
- 食物组使用稳定字符串 ID，计算结果只返回展示所需的布尔项和短文案。

#### 4.2.4 并发模型

- N/A：所有逻辑在 Vue 单线程事件循环中同步执行，无网络、异步写入或共享可变状态。

#### 4.2.5 错误处理

- UI 通过输入范围限制阻止非法月龄；纯函数对非法调用 fail-closed 并抛出 `TypeError`。
- 官方外链打不开时沿用项目现有安全链接提示，不回退到不可信地址。

### 4.3 核心逻辑实现

1. 月龄变化时，通过分段表一次匹配阶段建议。
2. 食物组变化时，对稳定 ID 去重并生成 Set，检查 4 类阈值和三个必需覆盖项。
3. 将阶段建议、搭配结果和安全提示分别呈现，避免用单一分数制造“营养达标”的错觉。
4. 弹框打开时聚焦关闭按钮，关闭后由 `useDialogFocus` 恢复原入口焦点。

### 4.4 方案优劣分析

- 优点：输入少、结果直接、离线可用、容易测试、健康风险边界清晰。
- 局限：不记录长期饮食，也不考虑实际份量、奶量、疾病、早产和个体营养需求。

## 5. 备选方案 (Alternatives Considered)

- 完整食谱推荐：内容维护成本高，且食材可获得性、文化习惯与过敏情况差异大，本期不采用。
- 精确克数/营养素计算：需要可靠食物成分库和个体参数，容易被误解为处方，本期不采用。
- 将结果持久化到云端：会引入 Schema 迁移和多孩冲突处理，不符合初版简约目标，本期不采用。

## 6. 业界调研 (Industry Research)

### 6.1 业界方案

- 世界卫生组织 2023 年指南把辅食阶段定义为通常从约 6 月龄开始至 23 月龄，强调食物多样性、逐步调整性状和回应式喂养。
- WHO 的最低餐次指标建议：母乳喂养儿童 6—8 月龄每天 2—3 餐，9—23 月龄每天 3—4 餐，并按需增加 1—2 次营养加餐。
- 中国 2025 年 0—3 岁婴幼儿营养喂养评估方案使用 7 类食物组，并将“每天至少 4 类，且包含富铁动物性食物、蔬果、谷薯”作为适宜性检查。
- CDC 的婴幼儿辅食建议强调约 6 月龄、准备信号、一次引入一种单一成分食物并观察 3—5 天，以及富铁食物和常见过敏原安全引入。

### 6.2 对比分析

- 本方案采用主流产品常见的“月龄指南 + 食物组打勾 + 即时结果”，但不加入难以验证的 AI 食谱生成。
- 以覆盖项和下一步建议代替精确营养评分，既保留可操作性，也避免错误精度。
- 中国官方 7 类食物组作为主要计算标准，WHO/CDC 用于餐次、性状和安全补充，适配主要用户场景。
